# 工作台 SPEC（AATD · 原创 v0.1）

状态：草案（无人值守，待晨审追认）。0 临床审核、0 患者访谈。本文定义 M2 原型与 M5 开发版的统一范围；家族通用契约引用编号文档，病种语义全部为本仓原创。

## 设计者与研究/场景依据

- 依据：DEV-REQUIREMENTS（功能线 F1–F5）、SCENARIOS（S1–S8，全部假设·改写）、PATIENT-FLOW、USER-RESEARCH（证据分层，0 访谈如实）、FAMILY-CONTRAST（基准移植）、CLINICAL-DATA（医学约束，阈值【待核】）。
- 用户需求证据 = 0（无访谈）；专业约束 = 文献/指南边界。取舍原则：患者信息整理 > 判定输出；判定输出 = 0。

## 问题、用户与最小闭环

- 输入：患者/家属记录症状、输注、两科化验单；医生原话。
- 动作：归档 → 核对入库 → 按日期并列回看 → 导出就诊材料。
- 输出：带来源的回看视图 + 就诊准备导出件。
- 失败恢复：缺失项显式留空；未核实项标【待核】；导入冲突进 import_conflict 不覆盖。
- 成功标准：一次记录可核对入库并导出同源材料（closure 见 DEV-REQUIREMENTS §二）。

## 方案与 ADR

- ADR-1 一病一仓（R2 FSHD 形态）而非模块挂靠：随访结构天然落在家族引擎上；已按 Issue #58 申报，服从 triage 调整。
- ADR-2 非肿瘤语义：发作—缓解、受累器官（肺/肝）、随访节律表达；不引入分期/线序/疗效/预后。
- ADR-3 布局 business-first：主区业务，右侧 AI 面板 35%（25–45% 可拖），不遮主滚动。
- 宿主能力表：见 docs/02-DSH-CONTRACT.md；本机核验在 M5/M6 执行，未核验版本号不复用。

## 数据与 API

- 实体与表见 M3：档案 2、指标 3、通用 7、专属 N（infusion_series/flare_episode/family_line）、导入 3。
- 事实与候选分离：ai_candidate 拒收零副作用；手工/AI/导入三通道同一事实层。
- 无判读列；派生值读时算不落库；ORDER BY rowid、显式 null、in_use、分节 *_title。
- 外部信息合同：指南与文献来源见 CLINICAL-DATA 证据台账；未核实项标【待核】，中国适应证只认官方来源；获取成功不等于医学正确，临床审核前一律占位。
