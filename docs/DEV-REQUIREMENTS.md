# 开发需求（AATD 工作台 · 原创）

版本：v0.1 草案（M0/M1）。头部红线：本文档为病种原创，未从家族任何仓 fork 复制；家族通用契约只引用编号文档。

## 一、服务对象与边界

- 服务主体：成人 α1-抗胰蛋白酶缺乏症（AATD）患者及家属。家属代记需标明记录者。家系成员筛查线索只记录医生原话与筛查条目事实，不判定家族成员风险。
- 病程覆盖：确诊后长期随访（呼吸科肺功能 + 消化科/肝病科肝功能 + 每周加强治疗输注登记 + 急性加重发作—缓解），不含确诊前筛查决策流程。
- 本工具不做的事：不输出诊断、风险分级、处置建议、预后判断；不把「该不该用加强治疗」「孩子会不会遗传」写成判定语。

## 二、患者视角功能线（每条挂场景，0 访谈如实标注）

> 0 患者访谈：以下场景为开发者基于病种公开资料的假设场景，全部为改写句，不冒充患者原话。待真实访谈补位后替换。

- F1 病程线：患者想知道「距上次急性加重多久了、加重过几次」。功能：发作—缓解时间线 + 近 90 天加重计数。验收：A/B 两套档案切换后时间线与计数同步且不串档。
- F2 化验核对：患者拿到呼吸科肺功能单与肝病科肝功能单，不知道能不能放一起比较。功能：指标按「方法/单位/机构可比组」分节，跨方法不合并、不做差、不连线。验收：跨方法合成数据下趋势图断线不连线（MT06 类断言出数字）。
- F3 输注登记：每周一次加强治疗输注，记不清输了多少次、漏了几周。功能：治疗折叠卡按「一段治疗/一次调药」分组，输注按次记录并计次，缺口周如实留空。验收：计次统计与演示数据逐条对账一致。
- F4 就诊准备：换科室就诊或复诊，想把两科指标与医生原话理成一页。功能：导出就诊准备材料（带来源与待问事项）。验收：导出文件与页内数据同源，抽查三条记录一致。
- F5 家系线索：家系成员问「我该不该也查一次」。功能：家系筛查线索清单，只列医生已说的话与筛查条目原文。验收：禁词检查器 0 命中（无「你应该检测/会遗传」类判定语）。

## 三、医生任务不冒充患者需求（独立评审一票否决）

排除项：量表评分自动解读、危险度分层、治疗时机推荐、生存/进展预测。医生相关任务（如指标参考范围展示）以「对照参考范围 · 需问医生」形式呈现，不生成判断。

## 四、数据与隐私

- 本机优先，SQLite 唯一存储；无静默上传。
- 私密三出口（看板/导出/AI 上下文）共用同一过滤函数，页内写「N 条中私密 M 条」。
- 无判读列：schema 无 diagnosis/risk_level/activity_score 类派生判定入库；派生值读时算，不落库。

## 五、可回退默认值（无人值守，待晨审追认）

见 docs/DEV-PLAN.md「可回退默认值」表：服务主体=成人患者及家属；病程覆盖=确诊后随访；MinerU=未接入；品牌占位名=小筛宝 A1Pal；试验线=四段链路裁剪执行；git=仅推自身私有仓，M7/M8 只备草稿。

## 六、验收与禁词

- 全站禁词：诊断建议、预后、生存期、疗效排序、分期/线序、肿瘤标志物话术、「你已进入 X 期」。
- 交付前 `npm run check` 全绿 + `npm test` 全过 + `dsh-wb-cli audit` fail 不交付。
- 三态汇报：实测通过 / 骨架 / 未实现；装机、真实数据、原生 AI、外部服务单独说明。
